# 1. Introduction

Wireshark is a powerful network protocol analyzer used for monitoring, troubleshooting, and analyzing network traffic in real time. This project focuses on understanding how different protocols such as HTTP, DNS, and TLS operate within a network environment. By capturing and inspecting packets, it becomes possible to understand communication between devices and servers.

The objective of this project was to:

* Capture live network packets using Wireshark.
* Analyze HTTP GET requests.
* Observe DNS query and response packets.
* Examine TLS handshake packets.
* Understand how network protocols communicate across different layers.

| ---------------------- | -------------------------------- |
| Source IP Address      | IP address of the client machine |

### Explanation

The GET request is used by a client to request data from a server. The packet captured showed that the browser requested a webpage from the server. Since HTTP is not encrypted, all information including headers and requested resources were visible in plain text.

The packet also contained important headers such as:

* Host
* User-Agent
* Accept
* Connection

This demonstrates how HTTP traffic can easily be inspected and monitored.

# 5. DNS Packet Analysis

## Display Filter Used

```text
dns
```

## Screenshot of DNS Query and Response

**[INSERT SCREENSHOT HERE]**

## Observations

The DNS packets showed how domain names are translated into IP addresses.

### Key Details Observed

| Field               | Description         |
| ------------------- | ------------------- |
| Query Name          | example.com         |
| Query Type          | A Record            |
| Response IP Address | Example resolved IP |
| Protocol            | DNS                 |
| Destination Port    | Port 53             |

### Explanation

When the domain name was entered into the browser, the computer first performed a DNS lookup to obtain the server IP address.

The DNS query packet contained:

* The requested domain name.
* The query type.
* Transaction ID.

The DNS response packet returned the IP address associated with the domain. This process is essential because computers communicate using IP addresses rather than domain names.

The analysis demonstrated how DNS operates as a foundational internet service.

# 6. TLS Handshake Analysis

## Display Filter Used

```text
tls
```

## Screenshot of TLS Client Hello and Server Hello

**[INSERT SCREENSHOT HERE]**

## Observations

The TLS packets showed the process of establishing a secure encrypted connection between the client and server.

### Key Details Observed

| Field              | Description                                         |
| ------------------ | --------------------------------------------------- |
| Protocol           | TLS                                                 |
| Client Hello       | Sent by the client to initiate secure communication |
| Server Hello       | Sent by the server in response                      |
| Encryption Methods | Supported cipher suites                             |
| Destination Port   | Port 443                                            |

### Explanation

The TLS handshake is responsible for setting up secure encrypted communication.

#### Client Hello

The Client Hello packet contained:

* Supported TLS versions.
* Cipher suites.
* Random values.
* Session information.

#### Server Hello

The Server Hello packet contained:

* Selected TLS version.
* Chosen cipher suite.
* Server certificate information.
* Session details.

Unlike HTTP traffic, HTTPS traffic is encrypted using TLS, making it difficult to inspect application data directly.

This demonstrated the importance of encryption in protecting sensitive information transmitted over the internet.

# 7. Comparison Between HTTP and HTTPS

| Feature         | HTTP       | HTTPS      |
| --------------- | ---------- | ---------- |
| Encryption      | No         | Yes        |
| Port Used       | 80         | 443        |
| Security Level  | Low        | High       |
| Data Visibility | Plain Text | Encrypted  |
| Protocol Used   | HTTP       | HTTP + TLS |

# 8. Challenges Encountered

During the packet analysis process, several challenges were encountered:

* Difficulty identifying relevant packets among large traffic captures.
* Some websites automatically redirected HTTP traffic to HTTPS.
* TLS encrypted packets limited visibility of actual content.
* Background applications generated additional unrelated traffic.

These challenges were managed using Wireshark display filters.
